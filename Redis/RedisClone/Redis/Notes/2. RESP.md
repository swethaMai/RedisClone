# RESP.js
## Definition
- REdis Serialization Protocol
- communicate with any Redis-server without Redis-client
- serialize different data types along with error-specific type
- used for TCP connections
- uses RESP2
## Working
- Encoder and decoder for Strings, Errors, Integers, Bulk Strings, Arrays
### Encoders
 - convert the given data to RESP encoding format
 - ends with CRLF
    - `\r` -> carriage return
    - `\n` -> line feed
    - makes it compatible with TCP parsing
#### encSimple
- +
- `+<string>\r\n`
#### encError
- -
- `-<error>\r\n`
#### encInteger
- :
- `:[<+|->]<value>\r\n`
#### encBulk
- $
- if null
    `$-1\r\n`
- if not null
    `$<length>\r\n<data>\r\n`
#### encArray
- *
- if null
    `*-1\r\n`
- if not null
    `*<number-of-elements>\r\n<element-1>...<element-n>`
- can obtain mixed data type elements
### Decoder
- parses one RESP frame
- returns
    1. node, nextOffset -> successfully parsed one frame
    2. needMore: true -> incomplete data
    3. protocolError: "...." -> malformed input
#### process
1. if start >= length of frame -> needMore
2. get prefix at `buf[start]`
    CR = 13 and LF = 10 -> ASCII value
3. readLine
    a. search for CR and LF
    b. get frame before CRLF
    c. move on to next frame after CRLF
    d. CRLF not found -> return null (incomplete)
4. parseIntegerLine
    a. if integer doesn't match pattern -> return null
    b. if matches -> convert to integer
    c. check if safe
        if safe -> return integer
        if not safe -> return null
    - used for bulk length, array length as well
5. based on prefix process the data 
    `{ node: { type: "datatype", value: data }, nextOffset: next }`
